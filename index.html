    Stage 3 · Write the image over fastboot (IDP)

    After stage 2 the provisioning agent runs Linux with the fastboot gadget (USB interface class ff/42/03, rpi-fastbootd). The station stages image.json from rpi-image-gen, the module creates its partitions and LUKS2 containers itself, then the station flashes each sparse image where the module asks (oem idpgetblk) — the sequence of rpi-image-gen/bin/idp.sh. A browser cannot write raw disks, so for a Chrome-only station this, not a USB mass-storage disk, is the transport. Not verified on hardware yet. Images larger than max-download-size need sparse splitting, which is not implemented.
